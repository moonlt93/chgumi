# 프로젝트 Codex 하네스

이 프로젝트에서는 작업 지침, 기존 코드 도구, 검증 근거를 연결해 Codex의 작업 품질을 관리한다.

## 구성

| 파일·명령 | 역할 |
| --- | --- |
| `AGENTS.md` | 제품 맥락, 구조, 가독성, 비밀키 취급, 검증·리뷰 기준 |
| `docs/code-conventions.md` | 코드 스타일의 상세 기준 |
| `docs/feedback-and-evaluation.md` | 현재 기능과 저장소·평가의 제약 |
| `docs/task-template.md` | 큰 작업의 완료 조건과 검증 결과 기록 |
| `npm run check` | 포맷 → lint → 타입 → 테스트 |
| `npm run verify` | check → webpack 프로덕션 빌드 |

`AGENTS.md`는 모델이 따를 지침이다. 비밀키 유출 방지나 명령 실행을 기술적으로 차단하는 보안 장치는 아니다. 자동 검증은 명령을 실행했을 때 동작하며, 현재 구성에는 커밋 훅·원격 CI·자동 배포를 추가하지 않았다. Codex의 기존 샌드박스와 승인 정책을 유지한다.

## 사용하는 방법

요청에는 원하는 결과와 확인 조건을 적으면 된다. 매번 아키텍처와 포맷 규칙을 반복할 필요가 없다.

> 피드백 전송 실패 시 재시도를 추가해줘. 같은 의견이 중복 저장되지 않아야 하고, 실패해도 현재 결과 이미지는 유지되어야 해. 구현하고 관련 테스트와 브라우저 동작까지 확인해줘.

분석만 원하면 “코드 수정 없이 원인과 대안을 비교해줘”처럼 범위를 지정한다. 큰 작업은 템플릿으로 계획·완료 근거를 남기고, 작은 수정은 최종 답변으로 충분하다.

새 Codex 작업을 이 저장소에서 시작한 뒤 “적용된 프로젝트 지침과 완료 기준을 요약해줘”로 로딩 여부를 확인한다. 공식 문서상 지침은 세션 시작 시 수집되므로 기존 세션에는 다시 읽도록 요청하거나 새 작업을 사용한다.

## 검증 명령

```bash
npm run check
npm run verify
```

외부 유료 API가 필요한 `npm run eval`은 포함하지 않는다. UI 검증은 별도로 개발 서버와 브라우저를 사용한다. 빌드는 `.next`와 Next.js 타입 파일을 생성할 수 있으므로 개발 서버와 동시 실행하지 않는다.

## 알려진 저장소 문제

현재 Git에 `node_modules`와 일부 `.next` 산출물이 추적되어 있다. `.gitignore`만으로 기존 추적이 해제되지는 않는다. 의존성 설치·빌드 후 소스 변경과 산출물 변경을 구분해서 검토해야 한다. 추적 해제는 별도의 저장소 정리 작업으로 다룬다.
