# CHUGUMI 제출용 구현 전략

## 목표

사진 한 장으로 상황과 추구미에 맞는 코디를 만들고, 구체적인 수정 요청을 반영해 입고 싶은 코디를 찾는다. 핵심 검증 질문은 “나의 모습이 유지되는가”와 “수정 후 실제로 입고 싶은가”이다.

## 최초 구현 기록

이 문서는 최초 구현 시점의 기록입니다. 이후 변경된 피드백 이벤트·평가·검토 화면의 현재 동작은 [피드백과 생성 평가](feedback-and-evaluation.md)를 기준으로 합니다.

1. 조건 선택: 자연스러운 변화/확실한 변화, 오버핏·강한 색·액세서리 제외.
2. 원본과 결과 비교: 동일 영역에 전체 사진을 표시하는 비교 슬라이더. 이미지 비율이 다르면 여백을 유지하며, 픽셀 정합이나 얼굴 인식 기능은 아니다.
3. 이유 기반 수정: 덜 화려하게, 덜 격식 있게, 단정한 핏, 여유로운 핏, 인물 보존. 원본 파일을 다시 보내고 서버가 이전 조건을 누적한다. 서로 반대되는 핏은 최신 선택으로 대체한다.
4. 기록: 생성 ID·세션·원본 해시·선택 조건·프롬프트 버전·부모 ID·성공/실패·소요 시간. 사진 바이너리는 이 저장소에 기록하지 않는다.
5. 피드백: 생성 ID와 신호만 받아 서버가 생성 기록 및 세션을 확인한다. 같은 생성/신호는 원자적으로 한 번만 저장한다. 명시적 평가는 다운로드보다 우선하고, LIKE/DISLIKE가 모두 있으면 더 나중에 처음 기록된 평가를 사용한다. 같은 신호를 다시 누르면 시각은 갱신되지 않는다.
6. 지표 분리: 성공 생성 수, 응답한 생성 수, 실패 수, 응답 기준 긍정률, 전체 생성 기준 긍정 비율을 구분한다. 무응답을 불만족으로 단정하지 않는다. 다른 추구미 탐색은 부정 평가로 기록하지 않는다.
7. 실험 분리: 수정 생성은 조건이 달라지므로 초기 프롬프트 실험 집계에서 제외한다. 초기 동률은 무작위 선택한다. 데이터가 적으므로 효과를 입증했다고 주장하지 않는다.
8. 구조: 생성 유스케이스에 프롬프트 Port를 주입한다. 평가 CLI는 같은 운영 프롬프트 함수를 사용하며 P0~P3는 과거 비교용으로 유지한다.

## 저장 및 배포

- `EXPERIMENT_DATA_DIR`에 영속 디스크 경로를 지정한다. 기본은 `data/experiments`.
- 단일 Node 서버와 로컬 파일시스템을 위한 어댑터다. 파일 rename/hard-link를 지원해야 한다. 서버리스 임시 디스크나 서로 다른 디스크를 사용하는 다중 서버에 그대로 배포하지 않는다.
- 구형 `data/feedback.jsonl`은 생성/세션 검증과 실제 분모가 없어 새 지표로 자동 이관하지 않는다. 파일 자체는 유지한다.
- 생성 성공 수는 서버가 완료한 결과 수다. 브라우저에서 실제 표시된 노출 수와는 다르다.
- 세션 쿠키는 HttpOnly, SameSite=Strict이며 production에서는 Secure다. 운영 서비스는 HTTPS로 제공한다.
- 사진과 결과는 브라우저 메모리에만 유지된다. 새로고침하면 다시 시작하며, 수정 이력의 이미지 비교/보관은 이번 범위에 없다.

## 다음 단계 우선순위

1. 실제 API로 생성·수정·저장 흐름 검증, 생성 시간과 비용 측정.
2. 체험 공개 전에 예산 상한, 생성 요청 제한, 호스팅 타임아웃과 이미지 업로드 제한 설정. 현재 애플리케이션에는 비용/요청 상한이 없다.
3. 사용자 5~10명에게 초기 결과/수정 결과를 비교하고 인물 보존·착용 의향·수정 만족도를 집계. 표본과 실패 사례를 함께 제시.
4. 필요할 때 품질 기준 미달 결과에 1회 재시도를 도입. 현재 보존은 프롬프트 지시이며 자동 보증하지 않는다.
5. 규모가 늘면 Repository Port를 DB 어댑터로 교체하고 인덱스, 세션별 제한, 기록 보관 기간을 설계한다.

## 검증

- `npm test`: 중복/무응답 집계, 세션 검증, 실패 기록, 원본 검증, 수정 누적, 파라미터 검증, 운영/평가 일치, 핏 충돌, 탐색 정책.
- `npm run typecheck`
- `npm run build -- --webpack`: 현재 환경에서 통과. 기본 Turbopack은 내부 포트 EPERM 오류로 실패했다.
- 브라우저: 조건 토글 및 결과가 없을 때 재시작 안내 확인.
- 외부 유료 API를 통한 실제 이미지 생성 및 품질 평가는 이번 검증에 포함하지 않았다.
