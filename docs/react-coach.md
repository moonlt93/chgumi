# 기록 기반 ReAct 코치

## 시작

기존 `.env.local`이 있다면 덮어쓰지 말고 다음 항목을 설정한다. 새 환경은 `.env.example`을 복사한 후 예시 키를 교체한다.

```dotenv
OPENAI_API_KEY=실제_키를_로컬에서_입력
COACH_MODEL=gpt-4.1-mini
AI_MODE=live
```

서버를 재시작하고 **오늘 → 내 기록으로 AI 제안 받기**를 누른다. 자동 페이지 로딩은 유료 호출을 하지 않는다. 계정의 API 결제·모델 접근 권한·네트워크 연결이 필요하다. 기본 모델 대신 Responses API, 함수 호출, 구조화 출력을 지원하는 접근 가능한 모델을 지정할 수 있다. 이미지 생성/평가용 모델 설정과 별개다.

키가 없으면 버튼을 비활성화하고 고정 샘플을 유지한다. 키 오류·한도 초과·시간 초과·잘못된 출력은 오류를 표시하고 샘플/직접 기록을 계속 사용할 수 있게 한다. 실패를 AI 성공 결과로 바꾸지 않는다.

## 실제 실행 구조

1. 쿠키의 사용자 ID로 서버 저장소를 조회하고 현재 입력에 맞는 캐시를 확인한다.
2. 캐시가 없으면 사용자별 요청 횟수를 저장소에 예약한다. Supabase 설정 시 DB, 미설정 로컬은 파일을 사용한다. Vercel에서는 AI_MODE=live를 명시해야 실제 API를 호출한다.
3. 모델이 읽기 도구를 선택한다(Action).
4. 서버가 허용된 도구를 실행하고 결과를 모델에 전달한다(Observation).
5. 모델은 추가 도구 또는 최종 제안을 선택한다. 최종 응답은 서버가 검증한다.
6. 결과를 사용자 JSON에 저장하고 코디 1개·활동 1개·짧은 응원 문구를 표시한다.

모델의 내부 추론을 저장하거나 화면에 노출하지 않는다. 표시하는 제안 이유는 사용자용 짧은 설명이고, 참고 정보 목록은 서버가 실제 실행한 도구 이름이다. 한 번의 고정 프롬프트 응답을 ReAct라고 표시하는 방식이 아니다.

| 읽기 도구 | 반환하는 정보 |
| --- | --- |
| get_persona | 선택한 페르소나 이름·설명, 사용자 목표 문장 |
| get_recent_records | 삭제하지 않은 최근 기록 최대 10개: 날짜·종류·제목·메모 최대 500자·느낌 |
| get_today_progress | 한국 기준 오늘 날짜, 이미 보상받은 실천 종류 |

사용자 표시 이름·세션 ID·사진·전체 보상 원장은 모델에 보내지 않는다. 도구는 사용자 ID나 파일 경로 인자를 받지 않는다. 현재 사용자 데이터만 읽으며 코인·기록·구매를 변경하는 도구가 없다.

## 한도와 저장

- 기본값: 생성 1회당 모델 요청 최대 4회, 도구 실행 최대 6회, 전체 모델 대기 45초, 모델 응답당 최대 출력 토큰 1600. 자동 API 재시도 없음.
- 사용자별 한국 날짜 기준 하루 최대 5회 시도, 신규 요청 사이 60초. 실패도 횟수에 포함한다. 새 쿠키 사용자까지 합친 서버 전체 지출 한도는 아니다.
- 같은 모델·날짜·페르소나·최근 기록·실천 현황은 캐시를 재사용한다. 캐시는 호출 횟수를 소비하지 않는다.
- 기록/목표 수정·삭제 시 기존 캐시는 무효화한다. 생성 도중 입력이 바뀌면 결과를 저장하지 않고 다시 요청하도록 안내한다.
- 캐시·사용량은 기존 사용자 JSON에 저장되어 서버 재시작 후에도 유지된다. 별도 DB/Redis 없음.
- Responses 요청에는 `store: false`를 사용한다. 이것이 서비스 제공자의 모든 로그·보관 정책을 비활성화한다는 뜻은 아니다.

## 피드백 반영과 보상

AI 제안에서 **실천했어요 · 기록하기**를 누르면 기존 기록 폼으로 연결된다. 제목과 종류가 채워지고, 사용자가 느낌·메모를 남긴다. 다음 AI 요청은 변경된 최근 기록을 읽는다. 어려웠다는 기록은 부담을 줄이고, 안 맞았다는 기록은 대안을 제안하도록 지시한다. 이는 요청 시 문맥 반영이며 모델 가중치 학습은 아니다.

추천 생성만으로 경험치·코인을 지급하지 않는다. 실제 기록 저장 시 기존 보상 규칙이 적용된다. 샘플 코디와 AI 코디는 같은 outfit 종류이므로 하루 보상을 중복 지급하지 않는다.

## 검증 범위

실제 키가 없는 개발 환경에서는 API 호출을 모킹해 도구 선택 → 결과 전달 → 구조화 응답 검증을 검사한다. 도구 제한·횟수 제한·자격 증명 오류·개인 데이터 범위·캐시·동시 요청·생성 중 입력 변경을 테스트한다. 실제 계정의 유료 호출 성공과 개인화 품질은 별도 확인이 필요하다.

## 공식 근거

- [OpenAI 함수 호출](https://developers.openai.com/api/docs/guides/function-calling): 모델의 함수 요청을 애플리케이션이 실행하고 결과를 다시 전달하는 방식.
- [GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini): 기본 모델의 지원 기능. 계정별 접근 권한은 실행 환경에서 확인해야 한다.
