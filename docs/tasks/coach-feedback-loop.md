# 사용자 행동을 반영하는 제안 반복

## 목표

페르소나·목표 문장 → 최근 행동 관찰 → 단계별 프롬프트 → 제안 → 선택 → 실천·느낌 기록 → 다음 제안으로 이어지는 흐름을 만든다.

## 범위와 완료 조건

- 기존 Responses 함수 호출 구조를 활용하며 별도 에이전트 프레임워크를 추가하지 않는다.
- 단계별 프롬프트에 현재 목표 우선, 긍정 경험 유지 후보, 어려움의 부담 완화, 맞지 않는 경험의 대안 탐색 기준을 적용한다.
- 제안에 ID·프롬프트 버전·모델·입력 기록 수·생성 결과·사용한 도구를 저장한다. 사용자별 최근 20회 유지.
- 선택과 완료/느낌을 구분하며 미선택을 싫어요로 취급하지 않는다. 선택에는 보상이 없다.
- 실천 기록은 서버가 소유권과 제안 종류를 확인한 뒤 제안 ID와 연결한다.
- 다음 요청에 현재 방향과 일치하는 최근 5회 제안, 각각 최근 3개 실천 결과를 제공한다. 삭제한 기록은 제외한다.

## 구현 계획

1. LifeState의 선택적 필드를 추가해 기존 JSON/DB 상태와 호환한다. 추가 SQL은 필요 없다.
2. 캐시 키에 프롬프트 버전과 관찰 데이터를 포함한다. 프로필·선택·기록 변경 시 무효화한다.
3. 같은 입력 재요청은 기존 결과를 반환하고, 새 기록만으로 유료 API를 자동 호출하지 않는다.
4. 모델의 내부 추론은 저장하지 않고 사용자에게 설명 가능한 제안 이유를 저장한다.

## 검증

- 43개 회귀 테스트와 webpack 프로덕션 빌드 통과.
- 브라우저에서 목표 변경·어려웠던 경험 기록·실제 코치 요청을 확인했다. OpenAI 429 응답으로 생성 실패, 오류와 기존 샘플 유지 확인.
- 실제 키 값은 출력하지 않았다. 실제 제안 성공 및 개선 효과는 미검증이다.
- 실제 Supabase에서 모킹한 제안 결과의 저장 → 선택 → 실천 → 다음 관찰 데이터 연결을 확인했다. 해당 스크립트의 테스트 데이터는 삭제했다.
- 사용자 요청에 따라 Vercel 배포는 사용자가 수행한다. 운영 도메인 기본값과 Supabase 연결은 이전 작업에서 구성했다.
