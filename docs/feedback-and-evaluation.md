# 피드백과 생성 평가

## 실행

- `.env.local`에 기존 이미지 생성 키를 설정한다. 키를 브라우저에 전달하는 `NEXT_PUBLIC_` 변수는 사용하지 않는다.
- `GENERATION_EVALUATION_ENABLED=true`이면 생성 완료 후 같은 원본과 결과를 평가 API에 보낸다. 기본값은 활성이다. 생성당 평가 호출 1회가 추가되고, 최대 15초의 평가 대기가 추가된다. 자동 재시도는 하지 않는다.
- `EVAL_MODEL`은 계정에서 접근 가능한 이미지 입력·구조화 출력 지원 모델로 설정한다. 실제 계정 접근과 품질은 배포 전에 확인해야 한다.
- 생성이 성공하면 평가 실패·비활성 여부와 관계없이 이미지를 반환한다. 응답 `X-Evaluation-Status`는 `COMPLETED / FAILED / SKIPPED`다. 프로세스 중단 시 저장된 `PENDING` 평가가 남을 수 있다.
- `REVIEW_ACCESS_TOKEN`에 무작위 24자 이상 문자열을 설정하면 `/review`에서 기록을 조회할 수 있다. 미설정 시 검토 API는 닫혀 있다. 접근 키는 브라우저 저장소나 URL에 저장하지 않는다. HTTPS를 사용한다.

## 피드백 계약

`POST /api/feedback`은 `eventId`, `generationId`, `signal`과 필요한 추가 필드를 받는다. 서버는 생성 소유 세션과 성공 상태를 검사한다.

| signal | 추가 필드 | 의미 |
| --- | --- | --- |
| LIKE | 없음 | 현재 결과의 착용 의향 긍정 |
| DISLIKE | 선택 reason | 현재 결과의 착용 의향 부정 |
| REPORT | IDENTITY_CHANGED 또는 BODY_CHANGED인 reason | 보존 문제 신고 |
| COMPARE | BETTER / SAME / WORSE인 comparison | 직전 결과와 비교. 부모 생성이 있어야 함 |
| DOWNLOAD | 없음 | 저장 행동. 만족도 보상에 포함하지 않음 |

- 같은 사용자 행동의 재전송은 같은 eventId를 사용한다. 동일 이벤트가 재전송되면 원래 기록을 반환한다.
- 새 의견은 새 eventId로 보낸다. 같은 ID로 내용을 바꾸면 거부한다.
- 저장소는 서버 수신 순서인 sequence를 부여한다. 현재 평가와 비교 의견은 각각 최신 sequence를 사용한다. 재전송이 최신 의견을 덮어쓰지 않는다.
- 품질 신고는 이력으로 남는다. 신고 철회 기능은 현재 없다. 불일치 표시는 과거 신고를 포함한 검토 후보이며 확정된 모델 오류가 아니다.
- `GET /api/feedback?generationId=...`로 같은 세션의 이력을 복원한다.
- 수정 요청은 기존 조건 누적 흐름을 사용한다. 이번 수정 요청을 영구 취향으로 저장하지 않는다.

## 평가 계약

`styling-judge-v1`은 identity, body, constraints, styling 각각에 `pass / fail / uncertain`과 관찰 근거를 기록한다. 점수 합산으로 보존 실패를 상쇄하지 않는다. 평가 모델의 판단을 사용자 취향이나 얼굴 인식 정확도로 표현하지 않는다.

원본·결과·상황·추구미·사용자 조건·누적 수정 이유를 함께 전달한다. 가려진 얼굴 등 판단 불가능한 경우 uncertain을 요구한다. 모델 응답은 JSON 구조와 필수 항목을 확인한 후 저장한다.

운영 생성과 `npm run eval`은 같은 `OpenAIStylingEvaluator`를 사용한다. CLI 보고서는 기존 숫자 점수에서 항목별 findings 형식으로 변경되었다. 예전 `sample-scores.json`은 과거 예시로 유지한다.

평가 API는 `store: false`로 호출한다. 애플리케이션이 원본·결과 이미지를 디스크에 저장하지 않는다는 뜻과 외부 API 제공자의 보관 정책은 구분해야 한다. 제공자 정책은 별도로 확인한다.

## 내부 검토

`GET /api/review`는 Authorization 헤더의 Bearer 접근 키를 확인한다. 20건씩 페이지를 나누고 다음을 반환한다.

- 생성 버전·상황·수정 조건·부모 생성 ID
- 평가 모델·평가 버전·판정·근거·소요 시간
- 최신 착용 의향·수정 전후 비교·전체 이벤트 이력
- 모델은 보존을 pass로 판단했으나 사용자는 보존 문제를 신고한 경우의 표시

세션 ID, 원본 해시, 이미지 바이트는 응답에서 제외한다. 사진을 저장하지 않으므로 이 화면만으로 이미지 재검증은 할 수 없다. 사진 기반 사후 검토는 향후 보관 동의·보관 기간·삭제 기능을 함께 구현해야 한다.

## 저장 범위와 제약

`EXPERIMENT_DATA_DIR/<generationId>/` 아래 generation.json, evaluation.json, feedback-events.json을 저장한다. 기존 LIKE.json 등은 읽어서 새 이벤트 파일에 포함하며 원본 파일은 삭제하지 않는다.

이벤트 저장은 프로세스 내 직렬화와 파일 원자 교체를 사용한다. 단일 Node 프로세스·영속 디스크용이다. 다중 프로세스/다중 서버에서는 DB의 트랜잭션과 `(generationId, eventId)` 유일 제약으로 대체해야 한다. 기존 이벤트를 전부 읽어 통계를 계산하므로 대규모 트래픽용 구현은 아니다.

브라우저는 원본·현재 결과·직전 결과만 메모리에 보관한다. 수정 실패 시 현재 결과를 유지하고, 다음 수정이 성공하면 더 오래된 결과 URL을 해제한다. 새로고침 시 이미지는 사라진다.

## 검증과 미검증 항목

회귀 테스트는 의견 변경·재전송·동시 이벤트·구형 기록·비교 자격·세션 격리·평가 실패·API 계약·접근 제어·URL 수명을 검사한다. 외부 API는 테스트 대체 응답을 사용한다.

실제 평가 정확도, 모델 접근 가능 여부, 비용, 사람과의 판정 일치율은 아직 측정하지 않았다. 자동 재생성·영구 개인화·사진 보관·배포는 활성화하지 않았다. 공개 체험 전 생성 요청 제한과 비용 상한을 별도로 설정해야 한다.
