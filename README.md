# CHUGUMI — 추구미 관리하는 남자

원하는 모습을 정하고, 코디·활동을 실천했다고 기록하면 경험치와 코인을 받아 캐릭터와 방을 꾸미는 **로컬 실행 MVP**입니다.

작은 실천을 기록하고 다시 돌아올 동기를 제공하는 것을 목표로 합니다. 실제 습관 형성·사용자 만족도·재방문 개선 효과는 아직 측정하지 않았습니다.

## 1. 현재 구현 범위

| 기능 | 실제 동작 |
| --- | --- |
| 페르소나 | 준비된 3가지 중 선택, 이름과 목표 문장 저장·수정 |
| 내 방 | 옆벽 없는 정면 고정 구도, CSS 3D 블록 캐릭터·가구 표시 |
| 오늘의 코디 | 미리 생성한 가을 착장 샘플 1개 표시. 사용자별로 새로 생성하지 않음 |
| 오늘의 활동 | 선택한 페르소나에 연결된 고정 활동 1개 표시 |
| 기록 기반 AI 코치 | 버튼 요청 시 페르소나·최근 기록을 읽는 ReAct 도구 반복으로 코디·활동·응원 생성. API 키 필요, 실호출 미검증 |
| 실천 기록 | 코디·활동·직접 기록 작성, 느낌 선택, 목록·종류별 필터, 메모 수정·기록 삭제 |
| 성장 | 서버가 정해진 규칙으로 경험치·코인 지급. 100 XP마다 레벨 1 증가 |
| 숍 | 준비된 상품 6개를 코인으로 구매. 현금 결제 없음 |
| 꾸미기 | 구매 전 미리보기, 구매한 물품 적용·해제. 가구는 고정 위치, 의상은 캐릭터 상의 색상 변경 |
| 저장 | 브라우저 식별 쿠키와 Supabase 사용자별 상태. Supabase 없는 로컬은 JSON 파일 사용 |
| 별도 AI 사진 스타일링 | API 키가 있을 때 기존 사진 생성 화면으로 연결. 아래의 별도 기능 설명 참고 |

**기본 샘플의 추천과 응원 문구는 고정 데이터입니다.** 별도의 `내 기록으로 AI 제안 받기` 버튼은 API 키가 있을 때 실제 API를 호출하도록 구현했습니다. 최근 기록의 느낌·메모를 다음 제안의 문맥으로 사용합니다. 모델 자체를 학습하지 않습니다.

## 2. 설치와 실행

### 준비

- Node.js와 npm: 개발·검증 환경은 Node.js **24.3.0**입니다. 설치 환경을 맞추려면 Node.js 24 계열을 사용하세요.
- 최초 의존성 설치에는 인터넷 연결 또는 필요한 패키지가 있는 npm 캐시가 필요합니다.
- 서버 프로세스가 프로젝트의 `data/` 폴더에 파일을 쓸 수 있어야 합니다.
- 별도 DB, Redis, Docker, AWS 계정은 기본 데모 실행에 필요하지 않습니다.

ZIP을 풀고 **package.json이 있는 폴더**에서 실행합니다.

```bash
npm ci
npm run build -- --webpack
npm start
```

브라우저에서 [http://localhost:3000](http://localhost:3000)을 엽니다. 기본 데모에는 `.env.local`이나 API 키가 필요하지 않습니다. 서버 종료는 터미널에서 `Ctrl+C`를 누릅니다.

개발 중에는 다음 명령을 사용합니다.

```bash
npm run dev
```

이 문서의 기본 주소는 3000 포트입니다. 앞서 브라우저 검증에 사용한 3100 포트는 별도로 지정한 테스트 서버입니다.

## 3. 처음 사용하는 순서 / 발표 시연

새 브라우저 사용자 기준 약 3분 동안 보여줄 수 있는 순서입니다. 이미 사용한 브라우저에는 이전 기록이 표시됩니다.

1. **시작 화면:** 이름 입력 → 페르소나 선택 → 선택적으로 목표 문장 입력 → `내 작은 방 만들기`.
2. **내 방:** 기본 캐릭터·방, 레벨 1, 0코인을 확인합니다.
3. **오늘:** `데모 · 준비된 코디와 활동 제안` 표시와 가을 코디를 확인합니다.
4. **기록:** `입어 봤어요` → 메모와 느낌 입력 → `기록 저장하기`. 실제 서비스에서는 실천한 내용을 기록하며, 발표에서는 시연용 기록임을 설명합니다.
5. **보상:** 첫 코디 기록으로 **20 XP·20코인**이 지급되고 기록 화면에 표시됩니다.
6. **숍:** 20코인인 `작은 초록 친구`를 구매합니다. 코인은 0이 되고 경험치는 유지됩니다.
7. **배치:** `내 방` → `내 방 꾸미기` → 화분의 `적용`. 책상 위에 화분이 나타납니다.
8. **저장 확인:** 새로고침하거나 서버를 종료·재실행합니다. 같은 브라우저 쿠키와 저장 폴더를 사용하면 기록·경험치·물품·배치가 유지됩니다.

추가로 보여줄 수 있는 동작:

- 코인이 부족한 상품을 구매하면 오류를 표시하고 지급하지 않습니다.
- 숍의 `미리보기`는 저장되지 않습니다. 구매 후 보관함에서 적용해야 합니다.
- 아바타를 누르면 인사·점프·기지개가 번갈아 재생됩니다. 아래 버튼으로 동작을 직접 선택할 수 있습니다. CSS 애니메이션이며 AI 동작 생성이 아닙니다.
- 방은 화면 높이와 표시 영역에 맞춰 같은 정면 구도로 비례 축소합니다. 안내 문구와 액션 버튼은 방 아래 별도 영역에 배치합니다. 높이가 작은 화면에서는 제목·목표 문장을 한 줄로 줄이며 전체 목표는 `목표 수정`에서 확인할 수 있습니다. 추가 기록·꾸미기 영역은 스크롤로 접근합니다.
- 기록의 `수정`은 메모를 바꿉니다. 제목·종류·느낌 수정 화면은 없습니다.
- 기록을 삭제해도 이미 받은 경험치·코인은 유지되고, 같은 날 같은 종류로 재등록해도 추가 보상을 받지 않습니다.

## 4. 보상과 구매 규칙

| 기록 종류 | 경험치 | 코인 | 지급 제한 |
| --- | ---: | ---: | --- |
| 코디 입어 보기 | 20 XP | 20 | 하루 1회 |
| 작은 활동 | 20 XP | 20 | 하루 1회 |
| 오늘의 기록 | 10 XP | 10 | 하루 1회 |

- 날짜는 **한국 시간(Asia/Seoul)** 기준입니다. 하루 최대 보상은 50 XP·50코인입니다.
- 보상 후에도 기록할 수 있지만 하루 기록 수는 삭제분 포함 20개까지입니다.
- 사용자의 **자기 신고**로 실천을 기록합니다. 사진·위치 인증이나 실제 행동 판별은 없습니다.
- 같은 행동을 다른 종류에 기록하는 것을 기술적으로 판별하지는 않습니다.
- 동일 ID의 같은 기록 재전송은 추가 보상을 주지 않습니다. 수정·삭제로 보상 한도가 초기화되지 않습니다.
- 레벨은 표시용 성장 수치입니다. 현재 상품에 레벨별 해금 조건은 없습니다.
- 상품은 계정 대신 브라우저에 연결된 사용자 단위로 한 번 구매합니다. 이미 보유한 상품을 다시 요청해도 코인을 추가 차감하지 않습니다.
- 구매·차감은 사용자 상태에 함께 저장합니다. 파일 저장소는 프로세스 내 순차 처리, Supabase는 revision 비교 후 원자적 갱신을 사용합니다.

## 5. AI는 어디에 사용되는가?

### 기록 기반 ReAct 코치 — API 키 설정 후 사용

`.env.local`에 `OPENAI_API_KEY`를 설정하고 서버를 재시작합니다. 코치 기본 모델은 `gpt-4.1-mini`이며 `COACH_MODEL`로 바꿀 수 있습니다. 오늘 화면에서 **내 기록으로 AI 제안 받기**를 누르면 실행합니다. API 결제·모델 접근 권한·연결 상태도 충족해야 합니다.

모델이 페르소나·최근 기록 조회 도구를 선택 → 서버가 현재 사용자의 데이터를 반환 → 모델이 추가 조회 또는 최종 제안을 선택합니다. 코디 1개, 활동 1개, 제안 이유와 짧은 응원을 반환하고 실제로 사용한 정보 항목을 표시합니다. 기록이 없으면 시작용 제안을 요청합니다.

전송 범위는 목표 문장과 최근 기록 최대 10개(제목·날짜·종류·느낌·메모 최대 500자), 현재 목표와 일치하는 최근 제안 5회의 선택·실천 결과, 필요 시 오늘 실천 현황입니다. 화면에서 전송 범위와 비용 발생을 안내하며, 버튼을 누르지 않으면 유료 호출하지 않습니다.

프롬프트는 **방향 확인 → 경험 관찰 → 부담·선호에 따른 조정 → 다음 행동 → 근거 검토** 순서로 구성합니다. **이 제안 해볼래요**는 관심 표현으로만 저장하며 보상을 주지 않습니다. **실천했어요 · 기록하기**로 제안과 행동·느낌을 연결하고 다음 요청에 반영합니다. 미선택이나 미기록은 부정 평가로 간주하지 않습니다. 최근 20회 제안의 결과·모델·프롬프트 버전·입력 기록 수를 저장하며 템플릿 자동 최적화나 모델 학습은 수행하지 않습니다.

동일 입력 결과는 선택된 저장소에서 재사용합니다. 사용자별 하루 5회 시도·1분 간격, 생성당 최대 4회 모델 요청·45초로 제한합니다. 실패도 시도 수에 포함합니다. 모델은 코인이나 구매 상태를 변경할 수 없습니다. Vercel에서는 `AI_MODE=live`도 설정해야 합니다. 상세 설정과 ReAct 구조는 [코치 안내](docs/react-coach.md)를 참고하세요.

**2026-09-18 실제 키로 코치 요청 1회를 시도했으나 OpenAI의 429 응답으로 생성하지 못했습니다.** API 사용 한도·결제 상태 확인이 필요합니다. 도구 왕복과 선택·실천 피드백 연결은 모킹 테스트로 검증했으며, 실제 추천 품질 개선은 미검증입니다.

### 기본 데모

- 오늘 화면의 인물·의류·착장 샘플은 사전에 AI 이미지 도구로 생성해 정적 파일로 포함했습니다.
- 샘플 경로: [public/test/virtual-try-on/autumn-01](public/test/virtual-try-on/autumn-01/README.md).
- 샘플 착장은 앱의 가상 피팅 API를 실행한 결과가 아닙니다. 현재 앱은 지정 의류 이미지를 입력받는 가상 피팅을 지원하지 않습니다.
- 페르소나 선택, 샘플 활동, 포인트 계산, 구매, 캐릭터 렌더링은 고정 데이터·일반 코드로 처리합니다.

### 별도 사진 스타일링 기능 — API 연결 코드 구현, 실제 호출 미검증

서버에 `OPENAI_API_KEY`가 설정되어 있으면 오늘 화면에 `내 사진으로 AI 코디 만들기` 링크가 나타납니다. 키가 있다는 사실만 확인하며 유효성·모델 사용 권한을 보장하지 않습니다.

```bash
cp .env.example .env.local
```

`.env.local`의 예시 키를 본인의 실제 키로 바꾸고, 사용할 수 있는 이미지·평가 모델을 설정한 다음 서버를 다시 실행합니다. 키를 README·ZIP·브라우저 코드에 넣지 않습니다.

구현된 흐름:

1. `/photo`에서 인물 사진 업로드.
2. 상황, 원하는 분위기, 스타일 조건 선택.
3. 서버가 이미지 편집 API에 사진과 프롬프트 전달.
4. 원본/결과 비교, 이유 기반 수정 요청, 좋아요·싫어요·보존 문제 신고·다운로드.
5. 활성화된 경우 항목별 AI 평가 결과를 별도 기록. 평가 실패가 성공한 이미지 반환을 막지 않도록 처리.

유의할 실제 제약:

- 이번 MVP 검증에서는 **유료 이미지 생성·AI 평가 API를 호출하지 않았습니다.** 연결 코드와 모킹 테스트 통과를 실제 생성 품질의 증거로 제시하지 않습니다.
- 생성 및 활성화된 평가에는 별도 API 비용이 발생합니다. 생성 비용 상한과 요청 속도 제한은 아직 없습니다.
- `GENERATION_EVALUATION_ENABLED=false`로 추가 평가 호출을 끌 수 있습니다.
- 사진 스타일링의 운영 세션 쿠키는 production 모드에서 Secure로 설정됩니다. 이 기능의 운영 시연은 HTTPS 환경이 필요합니다. 키 없는 생활 MVP의 로컬 HTTP 동작과 구분합니다.
- 사진 스타일링의 사진·결과는 브라우저 상태에 있으므로 새로고침하면 초기화됩니다. 생활 기록·구매 내역의 파일 저장과 다릅니다.
- 생성 결과와 생활 기록·보상은 자동 연결되어 있지 않습니다. 생활 화면에서 직접 기록해야 합니다.
- 생성 이미지를 3D 의상으로 변환하거나 옷의 실제 사이즈를 예측하지 않습니다.

사진 생성 프롬프트는 상황·분위기별 명시적 좋아요/싫어요 통계를 이용해 준비된 후보를 선택합니다. 모델 가중치를 학습하거나 개인의 생활 기록으로 취향을 학습하는 기능은 아닙니다. 상세 계약은 [피드백·평가 안내](docs/feedback-and-evaluation.md)에 있습니다.

## 6. 저장 방식과 운영 한계

**Vercel 설정은 [배포 안내](docs/vercel-deployment.md)를 따릅니다.** 운영 기본 도메인은 `https://chgumi.vercel.app`입니다. Supabase 환경변수 두 개와 SQL 적용이 필요합니다.

| 데이터 | 위치 / 방식 |
| --- | --- |
| 페르소나·기록·재화·보유/장착 물품 | Supabase `life_states`. 미설정 로컬은 `data/users/<사용자ID>.json` |
| 사용자 연결 | 임의 ID의 HttpOnly·SameSite 쿠키 |
| 사진 생성 메타데이터·피드백·평가 | `data/experiments/` |
| 데모 이미지 | `public/test/virtual-try-on/autumn-01/` |

`LIFE_DATA_DIR`, `EXPERIMENT_DATA_DIR`로 저장 위치를 변경할 수 있습니다.

- 파일 저장은 **단일 Node.js 프로세스와 영속 로컬 디스크**가 필요합니다. Supabase 생활 저장소는 revision 비교 후 원자적으로 갱신해 다중 인스턴스의 덮어쓰기를 방지합니다.
- 사진 생성의 실험 저장소는 파일 방식이므로 Vercel에서는 사진 생성 API를 비활성화했습니다. 생활 기능과 AI 코치는 별도입니다.
- 로그인, 다른 기기 동기화, 쿠키 분실 복구가 없습니다. 쿠키를 지우면 기존 파일은 남아도 기존 사용자로 연결되지 않습니다.
- 동일 브라우저 프로필에서는 같은 기록이 보이므로 개인 계정 인증이 필요한 서비스로 설명하지 않습니다.
- 서버 중지 후 저장 폴더를 복사해 백업할 수 있습니다. 자동 백업은 없습니다.
- 자유 가구 배치, 실제 3D 의상 메시, 사진 첨부 기록, 달력 UI는 미구현입니다. AI 활동 개인화는 최근 기록을 읽는 요청 단위 문맥 반영으로 구현했으며 효과 측정은 하지 않았습니다.

## 7. 검증 내역

2026-09-18까지 확인한 범위입니다.

- `npm run verify`: 포맷, ESLint, TypeScript, **테스트 43개**, webpack 프로덕션 빌드 통과.
- 실제 Supabase: 테스트 사용자 저장·재조회, 동일 기록 동시 재전송, 중복 구매 차감 방지, 사용자 격리 확인. 테스트 데이터 정리 완료.
- 실제 Supabase + 모킹한 모델: 제안·선택·실천 피드백 저장 및 다음 요청 입력 연결 확인. 실제 모델의 개선 효과 검증과는 구분합니다.
- 도메인 회귀 테스트: 운영 `chgumi.vercel.app`, Preview 배포 URL, 로컬 출처 허용 및 다른 출처 거부 확인. 실제 Vercel 배포는 사용자가 수행하며 이번 검증에 포함하지 않았습니다.
- 브라우저: 페르소나 저장 → 코디 기록 → 보상 → 화분 구매 → 배치, 잔액 부족 오류, 서버 재시작 후 상태 유지 확인.
- HTTP: 다른 출처 요청 403, 잘못된 JSON 400, 8KB 초과 요청 400 확인.
- 제출 ZIP 추출본: `npm ci --offline`로 캐시에서 설치하고 webpack 빌드 성공. 후속 정면 화면 수정은 본 프로젝트에서 재검증 후 ZIP에 반영했습니다.
- 실제 코치 요청은 OpenAI 429 응답으로 실패했습니다. 브라우저에서 오류 안내와 기존 기록·샘플 유지 확인. 실제 AI 결과 생성 성공, 사용자 대상 효과 검증, 부하 테스트, 다른 운영체제에서의 실행은 미검증입니다.

```bash
npm run check   # 포맷 + lint + 타입 + 테스트
npm run verify  # check + webpack 프로덕션 빌드
```

`npm run eval`은 별도 유료 API 실험이며 일반 검증에 포함되지 않습니다. [평가 실행 안내](evaluation/README.md)를 확인하세요.

## 8. ZIP 제출

Python 3가 있는 환경에서 실행합니다. 앱 자체 실행에는 Python이 필요하지 않습니다.

```bash
npm run package:submission
```

결과: `artifacts/chugumi-mvp.zip`

소스·잠금 파일·정적 샘플·문서를 포함하며, `node_modules`, `.next`, `.git`, 실제 환경 파일과 사용자 저장 데이터는 제외합니다. ZIP을 받은 사람은 압축을 풀고 2절의 설치·실행 순서를 따르면 됩니다.

## 발표용 요약

> CHUGUMI는 원하는 페르소나를 고르고, 코디와 활동을 실천했다고 기록하면 경험치와 코인을 받아 캐릭터와 방을 꾸미는 로컬 MVP입니다. 키 없이 고정 샘플로 체험할 수 있고, 키를 설정하면 기록을 조회하는 ReAct 코치와 사진 스타일링 API를 호출하도록 구현했습니다. 기록·보상·구매·저장은 실제로 동작합니다. 유료 API 실호출과 실제 사용자 효과는 아직 검증하지 않았습니다.
